Radiance renders a scene written in TypeScript on WebGPU. A scene is a graph of objects, a
camera looks at it, and a renderer draws it. The first renderer is a path tracer: every frame
adds samples to every pixel, so the picture starts noisy and sharpens while the camera rests.

## Requirements

- A browser with WebGPU. Chrome and Edge have it from version 113.
- A bundler that compiles TypeShade modules. The engine's kernels are `*.shade.ts` files; the
  compiler's Vite plugin, `typeshade/vite`, compiles them when your application imports the
  engine.

## Install

<Aside type="caution" title="Pre-release">
  The packages are not on npm yet. Until they are, clone the repository and use the workspace, as
  the steps under the command show.
</Aside>

```sh
npm install @typeshade/radiance @typeshade/radiance-addons typeshade
```

<Steps>

1. Clone the repository with its compiler submodule.

   ```sh
   git clone --recurse-submodules https://github.com/typeshade/radiance
   ```

2. Install the workspace.

   ```sh
   cd radiance && bun install
   ```

3. Run the site, which runs every example.

   ```sh
   bun run site:dev
   ```

</Steps>

## Configure Vite

Add the compiler's plugin, so the engine's kernels compile when Vite reads them.

```ts title="vite.config.ts"
import { defineConfig } from 'vite';
import { typeshade } from 'typeshade/vite';

export default defineConfig({ plugins: [typeshade()] });
```

## A first scene

This is the file the front page runs. It builds the scene, places a camera, starts the
renderer on a canvas, and gives the camera to the orbit controls.

<Code code={firstScene} lang="ts" title="first-scene.ts" />

What each part does:

- `Scene` is the root of the graph. `Mesh` joins a geometry and a material and is placed with
  `position`, `rotation` and `scale`, as in three.js.
- `PerspectiveCamera` looks down its own -z axis; `lookAt` turns it toward a point.
- `PathTracer` needs `await init()` before its first frame, because it requests a WebGPU
  device. `render(scene, camera)` adds samples and draws them.
- `setAnimationLoop` calls the callback once a display frame and waits for the frame before.
- `renderer.preview = 4` while the camera moves traces one pixel for each 4 by 4 block, so a
  drag stays smooth; at rest the full frame accumulates again.
